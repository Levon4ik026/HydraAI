# HydraAI — план стабилизации

## Цель
Сделать HydraAI надёжным Windows-приложением для наблюдения за EUR/USD, сбора котировок, воспроизводимого тестирования стратегий и анализа через локальную Qwen. Автоматическую торговлю не добавлять: сигналы остаются вспомогательной информацией для ручных решений.

## Правила работы
- Все изменения на ветке `hydra/stabilization`; `main` не менять без отдельного согласования.
- Не записывать API-ключи, токены, пароли и приватные данные в Git.
- Не создавать и не подставлять искусственные свечи.
- Не объявлять стратегию прибыльной до повторного воспроизводимого тестирования.
- Сначала исправить запуск и данные, затем тесты, ИИ, интерфейс и упаковку.

## Этап 1. Инвентаризация и стабильный запуск
1. Сверить реальные файлы репозитория с импортами и командами запуска.
2. Проверить отсутствующие модули и точки входа; не восстанавливать файлы вслепую — сначала проверить зависимости и вызовы.
3. Оставить один управляемый процесс приложения и контролируемое завершение только запущенных HydraAI дочерних процессов.
4. Исправить BAT/точку входа и добавить понятные сообщения об ошибках.

## Этап 2. Надёжность рыночных данных
1. Проверять обязательные поля, конечность и положительность цен, а также согласованность OHLC.
2. Хранить время внутри системы в UTC; отображать пользователю время GMT+3.
3. Объединять историю без дубликатов, сортировать по времени и явно отмечать пропуски.
4. Не считать горизонт в свечах равным минутам, если между свечами есть разрывы.
5. Добавить ограниченные повторы запросов, тайм-ауты, проверку свежести и понятное состояние источника.
6. Сохранять историю при перезапуске; не удалять старые данные автоматически без согласования.

## Этап 3. Проверяемые бэктесты
1. Зафиксировать правила входа, цену входа, момент экспирации, выплату и обработку ничьих.
2. Проверить хронологическое разделение данных и отсутствие утечки будущей информации.
3. Учитывать реальные временные интервалы и исключать сделки, пересекающие разрывы.
4. Пересчитать CALL и PUT для каждого горизонта на одном и том же наборе данных.
5. Выводить число сделок, выигрышей, проигрышей, ничьих, условный результат, просадку и параметры теста.
6. Сравнить результат с базовой случайной стратегией при тех же моментах входа и горизонтах.
7. Сохранять конфигурацию и используемый диапазон данных для повторения теста.

## Этап 4. Анализ через Qwen
1. Передавать модели только проверенный снимок данных с временными метками.
2. Указывать свежесть, полноту и наличие разрывов; при проблемах не выдавать уверенный вывод.
3. Разделить технические метрики и текстовую интерпретацию модели.
4. Не обещать точность, прибыль или гарантированный исход.
5. Запускать анализ по запросу пользователя или по явно включённому расписанию, а не бесконтрольно в цикле.

## Этап 5. Интерфейс
- Русский язык по умолчанию и переключение на английский.
- График EUR/USD, цена, таймфрейм, источник и время последнего обновления.
- Управление сбором данных и запуском анализа.
- Обзор рынка, результаты бэктестов и диагностика качества данных.
- Настройки источника и понятные предупреждения о неполных/устаревших данных.
- При выключенном сборе показывать сохранённую историю без скрытого фонового сбора.

## Этап 6. Сборка Windows
1. Упаковывать приложение только после прохождения тестов.
2. Зафиксировать зависимости и конфигурацию запуска.
3. Хранить ключи и рабочие данные вне бинарного файла.
4. Проверить чистую установку и запуск на Windows без dev-окружения.

## Известные риски, требующие перепроверки
- Ранее проверенный `start_hydra.bat` ссылался на отсутствующий `hydra_market_observer.py`.
- В `download_extended_history.py` обнаруживались неопределённые константы и проблемы отступов.
- Несколько исходных модулей, ранее присланных в переписке, не находились в текущем дереве GitHub; перед восстановлением сверить актуальную ветку и импорты.
- Старые результаты бэктестов и CSV требуют повторной проверки на разрывы, временные метки и правила входа/выхода.
- В репозитории ранее обнаруживался старый API-ключ. Не возвращать секреты в Git; проверить, что в конфигурации используется только локальный секрет, а в репозитории — безопасный шаблон.
