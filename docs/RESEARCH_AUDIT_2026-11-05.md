## 4. Аудит существующего backtest V3

Файл: `backtest_v3.py`.

Текущая логика:

- EMA20/EMA50 + RSI14.
- Экспирации: 1, 3, 5 и 10 минут.
- Сигнал формируется после закрытия свечи; вход моделируется по Open следующей свечи.
- Выход моделируется по Close свечи, соответствующей горизонту.
- Сделки не пересекаются.
- Разделение данных: первые 70% / последние 30%.
- Выплата жёстко задана как `PAYOUT = 0.80`.
- Скрипт не принимает индивидуальную выплату по каждой сделке.

Сохранённый `backtest_v3_summary.csv` для HOLDOUT при историческом допущении выплаты 80%:

## 6. Обязательные требования к новому исследовательскому стенду

1. Использовать только закрытые свечи; сигнал на свече N может использовать только данные, известные к её закрытию.
2. Вход моделировать не раньше следующего доступного момента после сигнала.
3. Экспирацию измерять реальным временем, а не только индексом строки; сделку через разрыв данных пропускать.
4. CALL и PUT оценивать отдельно.
5. Проверять горизонты 1, 2, 3 и 5 минут на M1; дополнительные горизонты — отдельными сценариями.
6. Выплату задавать на уровне сценария или отдельной сделки; не считать 92% постоянной ставкой.
7. Обязательно показывать число сделок, wins/losses/draws, win rate без ничьих, net profit, expectancy на сделку, максимальную просадку и максимальную серию проигрышей.
8. Сравнивать стратегию с базовыми сценариями на тех же временных точках входа.
9. Использовать хронологический train/validation/holdout и walk-forward; не подбирать параметры на финальном holdout.
10. Отдельно проверять устойчивость по торговым сессиям, волатильности и рыночным режимам.
11. Проверять расчёт индикаторов на эталонных наборах и исключать look-ahead bias.
12. Считать тест на Twelve Data предварительным; окончательную проверку проводить на независимых данных и котировках Pocket Option.
