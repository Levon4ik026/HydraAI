## Shared scheduler boundary correction (2026-11-08)

A consistency review found that `research.backtest_engine.backtest_signals` blocked a new signal on the candle where the previous trade expires. The trade settles at that candle's close; a signal evaluated on the same close can validly enter at the next candle open without overlapping. The production-style `hydra_math_core` scheduler already follows this boundary convention, but the research engine had an off-by-one restriction (`next_available_signal = exit_index + 1`). Corrected it to allow `signal_index == exit_index` and added a deterministic regression test proving that the entry of the second trade equals the first trade's settlement timestamp. The intermediate signal while the first trade is active remains blocked. Research-only correction; no Desktop or production file changed.


A second boundary-input issue was found in the same engine: NaN/Infinity values passed the old `draw_epsilon < 0` check, silently changing draw classification (NaN disables the comparison; +Infinity can classify every finite move as a draw). Validation now requires a finite, non-negative epsilon, with regression coverage for NaN, both infinities and a negative value. This is input hardening only; no signal or strategy parameter changed.


CI regression follow-up: the first run after enabling expiry-close entries correctly exposed an obsolete assertion in the older non-overlap test, which still expected the scheduler to skip the expiry candle. Updated that assertion to the now-explicit contract: signals during the active trade are skipped, while a signal on the expiry candle close is eligible. The dedicated boundary test remains as an independent regression check. The failure was in the stale test expectation, not in the corrected scheduler behavior.
